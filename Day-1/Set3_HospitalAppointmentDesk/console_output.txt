Comparative Takeaways:
  1. Swap Count: Selection Sort performed 2,988 swaps (at most n-1 = 2,999).
     Quick Sort performed 17,000 swaps (5x more memory writes).

  3. Trade-off: If memory writes are expensive (e.g. Flash/EEPROM devices), Selection Sort
     is optimal; for high-throughput roster sorting, Quick Sort is vastly superior.

Why a List Scan is Not Acceptable at this Volume:
  1. Complexity Bottleneck: An O(n^2) list scan performs n*(n-1)/2 = 12.5 million checks for 5,000 records.
     If the hospital expands to 50,000 bookings, the list scan requires 1.25 billion checks (over 45 seconds).
  2. Concurrency & Race Conditions: In a shared hospital roster where hundreds of receptionists
     book appointments simultaneously, locking the roster for tens of seconds causes catastrophic UI freezes.
  3. The Hash-based structure offers O(1) amortized lock-free verification, ensuring immediate booking feedback.

   TASK 5: DOCTOR SHIFT SCHEDULER - DYNAMIC PROGRAMMING VS GREEDY

Requested Overlapping Appointment Slots for Doctor's Shift:
  - [Minor Clinic A: 08:30-09:30 (60 min, Weight: 30)]
  - [Major Surgery B: 09:00-13:00 (240 min, Weight: 180)]
  - [Routine Followup: 12:30-13:30 (60 min, Weight: 30)]
  - [Cardiology Proc: 13:30-16:00 (150 min, Weight: 140)]

1. Greedy Selection (Earliest Finish Time First):
   - Greedy greedily selects 'Minor Clinic A' (finishes earliest at 09:30).
   - This blocks the 'Major Surgery B' (which started at 09:00).
   - Next, Greedy picks 'Routine Followup' (12:30-13:30), then 'Cardiology Proc' (13:30-16:00).
   => GREEDY RESULT: Total Value = 200 pts | Appointments: [[Minor Clinic A: 08:30-09:30 (60 min, Weight: 30)], [Routine Followup: 12:30-13:30 (60 min, Weight: 30)], [Cardiology Proc: 13:30-16:00 (150 min, Weight: 140)]]

2. Dynamic Programming Optimal Selection (Weighted Subproblem Tabulation):
   - DP evaluates choice at each interval: Include vs Exclude.
   - DP recognizes Major Surgery (180) + Cardiology (140) = 320 pts > Greedy's 200 pts!
   => DP OPTIMAL RESULT: Total Value = 320 pts | Appointments: [[Major Surgery B: 09:00-13:00 (240 min, Weight: 180)], [Cardiology Proc: 13:30-16:00 (150 min, Weight: 140)]]

| Algorithm            | Total Care Value  | Appointments Accepted | Optimality       |
+----------------------+-------------------+-----------------------+------------------+
| Greedy Approach      |            200 pts |                     3 | SUB-OPTIMAL      |

--- Algorithmic Conclusion ---
1. When appointment durations and patient acuity weights vary, the greedy-choice property fails.
2. Dynamic Programming computes the true globally optimal shift roster in O(n log n) time,
   maximizing physician clinical productivity and patient care outcome metrics.
