Theoretical Explanation:
  - Linear Search compares elements sequentially: Best=1, Average=n/2 (50,000), Worst=n (100,000).
  - Binary Search halves interval at every step: Best=1, Worst=ceil(log2(100,000)) = 17 comparisons.
  - In banking audits, 17 comparisons ensure deterministic sub-microsecond SLA regardless of table size.

--- Data Structure Justification & Complexity ---
1. Data Structure Choice: HashMap<String, List<Transaction>> with composite key.
2. Time Complexity: O(n) average.
   - Hashing the composite string (Account + Merchant + Amount) takes O(1) amortized time.
   - Each bucket contains only a tiny number of transactions (usually 1-2), making the 60s comparison O(1).
   - In contrast, a naive pairwise check takes O(n^2) = ~5 billion comparisons for 100k transactions!
3. Space Complexity: O(n) to store references in the hash table.
   - For 100,000 daily transactions, memory footprint is under 10 MB, perfectly suited for real-time stream ingestion.
